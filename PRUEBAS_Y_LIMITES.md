# Comprobaciones y límites

El resultado local verifica la preparación del repositorio. No es una aprobación
del uso docente. Los registros de la auditoría anterior conservan su fecha y alcance.

| Comprobación | Qué demuestra | Qué no demuestra |
| --- | --- | --- |
| Verificador Python | Consistencia de inventario, datos, rutas estáticas, procedencia y estructura | Exactitud científica integral, comportamiento del DOM o permisos completos |
| Construcción --check | Los generadores originales producen los dos HTML preservados | Ejecución de botones o compatibilidad institucional |
| Reproducción Node PB-01 | El módulo original descarta tres URL documentadas en un DOM simulado | Corrección del defecto ni resultado final de todos los observadores |
| Ocho controles de preparación | Se rechazan cambios de estado, evidencia alterada, ID duplicado, recurso ausente, identificador privado y HTML divergente; se preservan fuentes al construir | Exactitud científica o experiencia Moodle |
| CI preparado | Las mismas órdenes están definidas con permisos de lectura | Ejecución en GitHub antes de que se suba y se active allí |

Una futura corrección de PB-01 necesita una prueba de recursos de la propia ficha,
reservas ajenas, error de carga y mapas, además del recorrido completo en navegador
y Moodle. No cambie la prueba histórica para obtener un resultado verde.

Las referencias de v9 y PB-AUD-01 se conservan como historia. Si cambia una fuente
de trabajo, actualice los artefactos generados y el registro del cambio. No reescriba
una evidencia histórica como si la nueva comprobación hubiera ocurrido antes.
