# PB-28: Historial ZIP anidado domina el checkpoint

Prioridad: P1  
Estado de origen: Sobrecoste de paquete comprobado

Documento preparado; no se ha creado una incidencia remota.

## Evidencia

En C6.3.5 hay 3.455.348 bytes de runtime y 170.503.305 bytes de ZIP padre dentro de 175.401.241 bytes de miembros.

## Decisión propuesta

Separar entrega de ejecución, expediente de revisión y archivo histórico con referencias/hash.

## Motivo

El historial conserva trazabilidad, pero enviarlo dentro de cada entrega incrementa la carga y la confusión.

## Cambio histórico

C6.3.5 ya retuvo solo el padre inmediato, que a su vez conserva su genealogía.

## Comprobación del 24-10-2026

Inspección de tres niveles de C6.4.2 y conteo de miembros; el ZIP padre es el 97,2 % del contenido descomprimido de C6.3.5.

## Qué falta

Diseño y ensayo de un paquete reducido que preserve referencias verificables y criterios del proyecto.

## Qué se rompe si la decisión es errónea

Descargas difíciles, extracción innecesaria, confusión entre aplicación y expediente; no se ha medido latencia de Moodle causada por este tamaño.

## Criterio de cierre

Runtime separado con inventario/hash y expediente que permite recuperar la genealogía original.

## Reversión propuesta

Conservar los ZIP originales íntegros; revertir el empaquetado sin borrar antecedentes.
